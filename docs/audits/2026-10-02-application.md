# Application UX audit — 2026-10-02

## Scope and method

Static source review of the React/Vite route tree, shared navigation/search, Atlas, account and studio access, the editorial and role workspaces, searchable selectors, and the cellar's shared responsive styles. The route inventory covers all page families registered in `src/App.tsx` and the imported business, learning, tasting, and cellar experiences. The root audit initially reproduced a 320 px global-search overlay issue (bottom navigation above the dialog, Escape did not close it); after the dialog change, root verified search result discovery and Escape dismissal at 390 px. Root also checked that an empty journey cannot be saved or previewed. No production or database writes were made. No catalog facts or localized knowledge content were changed in this audit.

## Prioritized findings

| Priority | Finding | Evidence and impact | Disposition |
| --- | --- | --- | --- |
| P1 | Search dialog is below the mobile navigation and does not isolate the page. | At 320 px, the bottom navigation remained visible over the overlay and Escape did not close it. The overlay was rendered inside the app root with a lower stacking level than the mobile nav; underlying controls remained reachable. | Fixed with a body portal, app-root inertness, focus containment/restore, Escape dismissal, and scroll locking. Shared dialog handling is also applied to AuthSheet and event checkout. Root verified Escape and result discovery after the fix at 390 px. |
| P1 | Journey completion is stored under a journey-only key. | `JourneyExperience` used `vine-atlas-journey-progress:${journey.id}`; two accounts on the same browser could observe and overwrite each other's completion. | Fixed to read/write only a user-scoped key. The old unscoped value is neither read nor migrated because its owner cannot be determined. |
| P2 | Atlas controls are duplicated without telling users they are synchronized. | Search, country, variety, and sort appear above the map and again above the directory, but there is one state model. Search inputs have no accessible names and only the first control group had a clear action. | Retain both requested locations; label the map and directory groups as two views of the same refinements, add accessible names and clear actions in both, and keep all filters bound to shared state. |
| P2 | Atlas selection can outlive the active filter result. | The inspector defaults to Mosel independently of current results. A country/grape/query filter can remove that selection while the inspector still presents it as selected. | Move selection to the first matching map result when the current selection is filtered out; keep the no-results state intact. |
| P2 | Search suggestions do not cover their own advertised content, and matching is brittle. | “Brioche” is a suggestion, but aroma records were not searched; curricula were also omitted. Leading/trailing query whitespace can produce false no-results. | Search all aromas and learning modules using locale-aware display fields; trim and normalize accents/case. |
| P2 | Professional/admin entry is easy to miss on mobile and Studio copy describes internal architecture. | Studio/Admin are absent from the five-item mobile nav but already present in Profile settings. That entry reused “Manage a private table, public events, a partner mini-site and commercial layers without mixing them with editorial truth,” which is abstract implementation language. | Keep the existing Profile links, improve their role-action description in EN/DE/FR/ES, and reinforce focus/target sizing on mobile. |
| P2 | Account-role loading and save states can look like an empty account list. | The manager starts with an empty array and shows “No matching accounts” even while loading or after a request error; status messages are not announced, and unchanged records can still be saved. | Add localized loading/error distinctions, status semantics, pressed states, focus visibility, and disable unchanged saves. |
| P2 | Searchable selectors are only partly keyboard-operable. | Arrow/Enter handling exists only on the search input; active options have visual styling but no `aria-activedescendant`, while option buttons remain tabbable inside a listbox. Focus is not restored to the trigger on close. | Implement a consistent combobox/listbox keyboard model for single and multi-select, focus restoration, and active-option announcements. |
| P2 | The cellar filter row is clipped at phone widths. | At `max-width:520px`, CSS resets the state-filter group's full-width grid placement to `auto` while the command bar remains two columns; its contents then compete with sorting inside a half-width cell. | Keep search, filters, and sort on deliberate full-width rows at narrow widths; let the state choices wrap instead of clipping. |
| P2 | Editorial catalog search has no empty result state. | The catalog list maps an empty result to an empty table while pagination remains visible, unlike the separate useful draft empty state. | Add localized no-results text and a clear-search/filter action. |
| P1 | Cleared regional and producer fields can leave empty content panels. | The content audit is removing unsupported generated region and producer fields; route components previously rendered cards and summaries without checking whether those fields had evidence. | Region and producer detail panels, map facts, and journey facts now render only non-empty fields. Grape detail and journey fact panels were also made conditional so they follow any fields cleared by the content audit. |
| P2 | Journey creation can produce an unusable empty room. | A builder journey could previously be saved and previewed with a generic title and zero chapters. | Require a trimmed title and at least one chapter before enabling save/preview; surface localized validation and save-failure feedback. Root verified empty-journey actions are disabled. |
| P2 | Direct tasting-room deep links are sign-in guarded. | `/tastings/:id` currently routes through the authenticated room, so an invitee following a public link may be sent through sign-in before joining. Changing this could affect the trust boundary around host controls and participant access. | Documented for product/security review; this audit does not create an anonymous-access path or weaken the existing guard. |
| P2 | Region intro copy wraps complete soil notes in a generated noun phrase. | Some localized soil fields are full editorial sentences; interpolating them into a lowercased “ground” sentence can produce malformed grammar and duplicate interpretation. | Region intros now render climate and soil as separate intact source paragraphs, with exact duplicate text suppressed. No seed-terrain fallback is used when the soil field is empty. |
| P2 | Region portrait exposes production labels to visitors. | The portrait used “Illustration subject” and “Catalogue centre” labels, which describe image production/catalog internals rather than the region. | Removed the subject label while retaining the image caption; replaced internal coordinate labels with plain location wording in all four locales. Portrait climate/soil facts also hide when empty. |
| P2 | Grape summaries wrap translated morphology fragments in generic prose. | The summary template describes a full sourced cluster sentence as the object of “field record says,” then wraps a separate berry phrase in “berries are described as,” producing malformed grammar in each locale. Some German morphology terms also translate leaf sinuses as “Nebenhöhlen” and early grape drop as “Weinabfall.” | Summaries now append the sourced cluster sentence intact and use a correctly inflected berry-colour adjective. A shared evidence normalizer repairs only clear terminology/translation errors; direct evidence consumers use the same helper. OIV terminology defines leaf sinuses as blade indentations; PlantGrape’s Riesling source says “early grape drop.” |
| P2 | Optional bottle-photo preview dominates the narrow-screen add sheet. | At 320 px, the empty 190 px preview is stacked above photo copy and upload actions, pushing the actual catalogue/name picker far down the sheet. | At phone widths, the photo row is now a compact thumbnail beside the copy/actions. The uploaded preview remains visible and has localized alt text. |
| P2 | Style-context wine summaries read like internal relationship data. | The summary presented a wine as “linked” to a producer and region and described variety IDs as a listed blend, although the record provides no blend proportions. | All four locales now introduce the wine naturally by name, producer, style, and region. The separate varieties line says which varieties are named and explicitly avoids asserting proportions. |
| P2 | Regional evidence profiles wrap climate/soil values in field-oriented or ungrammatical sentences. | The 34 evidence-backed profile records could begin with a lowercase climate term, while soil copy called the source a “note” and then wrapped a list in generic commentary. | Profile-only copy now uses complete localized climate and soil sentences (for example, “Die Böden umfassen…”), using only the existing extracted terms. Empty/unsupported records do not regain heuristic climate or soil content. |
| P2 | German winemaking copy calls berry crushing “Mahlen.” | The German vine-to-glass step and related educational copy used a term associated with milling rather than the standard description of breaking grape berries. | Replaced it with “Quetschen” and “Entrappen” where relevant. The German Wine Institute describes berries as being crushed (“zerquetscht”) and uses “entrappen” for removing stems ([Weinbereitung im Keller](https://www.deutscheweine.de/wein-speise/173/weinbereitung-im-keller/)). |

## Coverage limits / remaining risks

- This source audit does not certify editorial truth, provenance quality, or regional coverage; those are handled by the content audit and catalog validation. Region copy now displays only the climate/soil fields supplied by localized content rather than regenerating a soil explanation from fallback data.
- Root verified the search overlay at 390 px and the empty-builder disabled state, but other viewport families and dynamic record/detail routes still need the combined regression pass after implementation.
- Authenticated API failure and empty states are addressed in the role manager, but successful production administration depends on the configured account service and was not exercised here.
- The cellar modal's existing portal/focus behavior was reviewed as context but not refactored in this source scope.
- One combined release build should be run after all agents' changes are integrated; this agent does not run a competing build. No anonymous public tasting-room access was added; the route guard remains an explicit follow-up decision.
